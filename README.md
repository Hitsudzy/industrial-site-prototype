# Прототип корпоративного сайта «Компания»

Кликабельный статический прототип сайта инжиниринговой компании. Обезличен:
компания называется «Компания», логотип — нейтральный плейсхолдер, надпись
в знаке — временная, тексты — «рыба». Закрыт от индексации (`noindex, nofollow` в каждой странице и
`robots.txt`).

Чистый HTML/CSS/JS без сборки и без зависимостей: папка отдаётся как есть
(GitHub Pages или любой статический сервер). Все пути относительные, поэтому
сайт работает и из корня домена, и из подпапки `/<repo>/`.

## Как открыть локально

```sh
cd prototype
python3 -m http.server 8000
```

Открыть <http://localhost:8000/>. Двойной щелчок по `index.html` (схема
`file://`) тоже работает, но часть браузеров ограничивает `localStorage` для
`file://` — выбор концепции тогда передаётся только через параметр `?c=` в
адресе.

## Страницы

| Файл | Что это |
|---|---|
| `index.html` | Главная: первый экран, приветствие, направления (3 карточки), ключевые проекты (4 карточки), цифры, новости, партнёры, контакты с формой «Направить запрос» (`#request`) |
| `project.html` | Страница проекта (пример — «Шкафы АСУ ТП для энергоблока АЭС»): заголовок и лид, «спецификация» проекта, этапы работ, «Что сделано», галерея-коллаж с лайтбоксом, связанная услуга, другие проекты, CTA «Обсудить задачу» |
| `company.html`, `services.html`, `projects.html`, `news.html`, `licenses.html`, `partners.html`, `contacts.html`, `privacy.html` | Заглушки «раздел в разработке» в том же оформлении |

Каждая секция главной и страницы проекта помечена `data-block="<имя>"` и
`id` — по ним последующие задачи заменяют плейсхолдеры настоящей вёрсткой.

## Как устроены концепции A/B

- **A «инженерный тёмный»** — графит и тёмно-синий фон, циановый акцент,
  тонкая «чертёжная» сетка на фоне, моноширинные подписи.
- **B «корпоративный светлый»** — белый фон, тёмно-синий текст, тёмный первый
  экран и подвал, спокойный синий акцент, мягкие тени и скругления, шрифт
  Inter вместо Plex. На главной у B своя раскладка блоков (см. ниже).

Механика:

1. Тема целиком задаётся токенами — CSS custom properties в
   `assets/css/tokens.css`. Блоки `:root[data-concept="a"]` и
   `:root[data-concept="b"]` переопределяют одни и те же переменные
   (цвета, радиусы, тени, сетка, шрифт подписей). Компоненты в
   `assets/css/base.css` используют только переменные, без «сырых» цветов.
2. Класс `.theme-inverse` переводит блок на «инверсную» поверхность
   (первый экран, подвал, CTA-полосы): в B это тёмно-синий фон со светлым
   текстом, в A — ещё более тёмный графит.
3. `assets/js/concept-init.js` подключён синхронно в `<head>` и до первой
   отрисовки ставит `data-concept` на `<html>`. Приоритет: параметр адреса
   `?c=a|b` → `localStorage` (ключ `proto-concept`) → по умолчанию `a`.
   Все обращения к `localStorage` обёрнуты в `try/catch`.
4. `assets/js/main.js` (с `defer`) оживляет кнопку-переключатель в правом
   нижнем углу, при переключении обновляет `data-concept`, `localStorage`,
   параметр `?c=` в адресной строке и дописывает `?c=` ко всем внутренним
   ссылкам — поэтому выбор сохраняется при переходах даже там, где хранилище
   недоступно. Ссылку вида `index.html?c=b` можно отправить, и она откроется
   сразу в нужной концепции.

Чтобы добавить токен — объявить его в обоих блоках концепций в
`tokens.css` (и в `--inv-*`, если он нужен на инверсной поверхности).

## Главная в концепции B

Тот же `index.html`, другая раскладка — в `assets/css/home-b.css`
(подключён только на главной, после `blocks.css`). Каждое правило файла
начинается с `:root[data-concept="b"]`, поэтому A он не задевает. Характер B:
солидный светлый B2B-сайт, много воздуха, крупная спокойная типографика
(Inter, лёгкие крупные цифры), без моноширинных подписей, нумерации «01 /»,
чертёжной сетки и уголков; вместо них — мягкие тени, большие скругления
и «фото-ощущение» от кодовых градиентных панелей (токен `--illus-bg`).

| Блок | A «инженерный тёмный» | B «корпоративный светлый» |
|---|---|---|
| Первый экран | тёмный, сетка, сканирующая линия | тёмно-синий со скруглённым низом, очень крупный заголовок, кнопки-«пилюли» |
| Заголовки секций | линия с акцентным отрезком, «01 / Раздел» моноширинным | без линии и номера, подпись — светло-синяя «пилюля» |
| 01 Приветствие | портрет-чертёж слева, текст справа | цитата с крупной кавычкой на светло-серой панели, силуэт на градиенте справа |
| 02 Направления | карточки с иконкой в рамке и номером | карточки без рамки с тенью, сверху градиентная иллюстрация с иконкой в круге |
| 03 Проекты | 4 равные карточки | одна крупная карточка слева + список из трёх строк справа (от 1000 px; от 600 px — строки с миниатюрой) |
| 04 Цифры | тёмная сетка ячеек, моноширинные цифры | светлая полоса, тонкие разделители, крупные светлые (300) цифры |
| 05 Новости | 3 карточки | список строк: дата · заголовок и анонс · круглая стрелка |
| 06 Партнёры | сетка ячеек с рамками | светло-серая лента знаков, 4 × 2 (2 колонки на телефоне) |
| 07 Контакты | форма в рамке рядом со списком реквизитов | светло-серый фон секции, белая карточка формы с глубокой тенью |

Номера разделов в подписях обёрнуты в `<span class="eyebrow__num">` — B их
прячет. Токены, нужные только раскладке B (`--tint`, `--tint-strong`,
`--illus-bg`, `--shadow-lg`, `--radius-xl`), объявлены в обоих блоках
концепций в `tokens.css`; в A у них нейтральные значения и A их не использует.

## Знак и иллюстрации

### Как поменять текст знака

Пятиугольный знак на первом экране — inline SVG в `index.html` (ищите
`class="sign hero__sign"`, над ним комментарий). Текст правится в двух местах
внутри этого `<svg>`:

1. `<text class="sign__text" …>Надёжность</text>` — то, что нарисовано;
2. `<title id="sign-title">Знак компании «Надёжность»</title>` — то, что
   читает скринридер.

Регистр задаёт CSS (в A — прописными, в B — как написано). Если слово шире
внутренней рамки, `assets/js/main.js` сам ужимает его до `data-max` (в единицах
`viewBox`). Цвета и шрифт знака — классы `.sign__*` в `assets/css/base.css` и
токены `--sign-*` в `tokens.css`; графика A и B — две группы `sign__art--a` и
`sign__art--b` в том же `<svg>`.

### Фон первого экрана и шкаф

Нарисованы кодом скриптом `tools/gen_art.py` (без растров) и лежат в
`assets/img/`:

| Файл | Где используется |
|---|---|
| `hero-a.svg`, `hero-b.svg` | фон первого экрана главной — токен `--hero-art` в `tokens.css` |
| `cabinet-a.svg`, `cabinet-b.svg` | условный «3D-шкаф» (изометрия) в галерее `project.html` |

Готовые SVG закоммичены, сборка не нужна; скрипт запускают только после
правки рисунков: `python3 tools/gen_art.py`. Картинки под концепцию
переключаются парой `<img class="only-a">` / `<img class="only-b">`.

Поверх фона лежит затемняющая подложка (`.hero__art::after` в `base.css`),
поэтому текст первого экрана держит контраст AA. Худший случай проверяет
`python3 tools/check_hero_contrast.py` (код выхода 0 — все пары ≥ 4.5:1).
В A по фону медленно проходит «сканирующая» линия; при
`prefers-reduced-motion: reduce` она скрыта.

## Блоки главной и форма запроса

Вёрстка секций главной — в `assets/css/blocks.css` (подключён в
`index.html`; внутренние страницы могут подключить его и переиспользовать
классы `.card`, `.card-grid`, `.figures`, `.partners`, `.request`, `.field`).
Цвета только из токенов; токены блоков (`--tick`, `--card-lift`,
`--figure-*`, `--field-*`, `--color-error`, `--color-success`,
`--partner-ink`, `--check-icon`) объявлены в обоих блоках концепций в
`tokens.css`, поэтому B меняет вид без правки HTML.

Карточка кликабельна целиком через растянутую ссылку в заголовке
(`.card__link::after`) — одна остановка Tab на карточку, рамка фокуса
обводит всю карточку.

Форма «Направить запрос» (`id="request"`) обслуживается
`assets/js/request-form.js` (подключается к любой `form[data-request-form]`).
В прототипе она **ничего не отправляет**: скрипт проверяет поля
(обязательные: контактное лицо, e-mail или телефон, задача, согласие на
обработку ПДн), помечает ошибки `aria-invalid` и текстом, связанным через
`aria-describedby`, переводит фокус на первое ошибочное поле и сообщает
результат в `role="status"`; при успехе — «В прототипе форма не
отправляется». Без JS работает только встроенная проверка браузера
`required`, а отправка уйдёт POST-запросом на тот же адрес (статический
сервер ответит ошибкой) — для прототипа это допустимо.

Показатели в блоке «Цифры», новости, роли и годы проектов, контакты — рыба
(помечено HTML-комментариями).

## Страница проекта

`project.html` — образец страницы проекта; стили — `assets/css/project.css`
(подключается после `blocks.css` и переиспользует `.card`, `.label`,
`.frame-ticks`, `.grid-surface`, `.cover__*`). Цвета только из токенов, поэтому
концепция B переодевает страницу без правки HTML.

- **Шапка** (`data-block="project-head"`): цепочка, заголовок, лид и
  «спецификация» `.spec` — `<dl>` из нумерованных строк (объект, заказчик,
  годы, роль, направление со ссылкой на услугу). Заказчик и годы — условные.
- **Описание работ** (`#scope`): этапы `ol.stages` — вертикальная линия до
  1100 px, горизонтальная из 7 шагов шире; текст и блок «Что сделано»
  (цифры условные).
- **Галерея** (`#gallery`): `ul.gallery[data-lightbox]` — 6 элементов в
  асимметричной сетке (12 колонок от 1100 px, 2 колонки от 720 px, одна на
  телефоне). Каждый элемент — `<figure>` с кнопкой `[data-lightbox-item]`
  и подписью. Рисунки: шкаф — `cabinet-a/b.svg`, остальные пять — inline SVG
  из `tools/gen_gallery.py` (см. ниже).
- **Лайтбокс** — `assets/js/lightbox.js`, без библиотек. Открывается кликом
  или Enter/Пробелом по элементу галереи; диалог `role="dialog"`,
  `aria-modal="true"`, подпись — `aria-labelledby`, счётчик —
  `aria-describedby`. Закрытие: Esc, кнопка, клик по фону; ←/→ листают по
  кругу. Пока диалог открыт, остальная страница `inert`, Tab не выходит из
  диалога, прокрутка страницы заблокирована; после закрытия фокус
  возвращается на элемент, который открыл диалог. Картинка в диалоге —
  копия содержимого `.gallery__media`, поэтому пара `only-a/only-b`
  продолжает переключаться с концепцией.
- **Связанная услуга**, **Другие проекты** (те же карточки, что на главной)
  и **CTA-полоса** — кнопка «Обсудить задачу» ведёт на форму
  `index.html#request`.

### Страница проекта в концепции B

Тот же `project.html`, другая подача — в `assets/css/project-b.css`
(подключён только на странице проекта, после `project.css`). Как и
`home-b.css`, каждое правило начинается с `:root[data-concept="b"]`, поэтому A
не меняется (проверено попиксельным сравнением скриншотов A до/после на
360/768/1440/1920 px). Общие для B детали (подпись-«пилюля», кнопки-«пилюли»,
карточки без рамки с мягкой тенью) повторяют главную B.

| Блок | A «инженерный тёмный» | B «корпоративный светлый» |
|---|---|---|
| Шапка | заголовок над чертёжной «спецификацией» | светло-серая панель со скруглённым низом, очень крупный заголовок, лид крупнее |
| Спецификация | таблица-штамп «Лист 1 / 1» с номерами строк и моноширинными подписями | белая «карточка фактов» с глубокой тенью: подпись слева, значение справа, тонкие разделители, без номеров |
| Заголовки секций | линия с акцентным отрезком, «01 / Раздел» моноширинным | без линии и номера, подпись — светло-синяя «пилюля» |
| 01 Этапы | квадратные маркеры с моноширинными номерами | светло-синие кружки с номером в Inter на тонкой линии, больше воздуха |
| 01 Текст и «Что сделано» | текст рядом с карточкой-перечнем цифр | текст в три колонки (от 960 px), «Что сделано» — светлая полоса во всю ширину: крупные светлые (300) цифры, единицы синим, 3 + 2 в ряд |
| 02 Галерея | плитки в рамке с сеткой, номер в подписи, уголки | скруглённые плитки с мягкой тенью на градиентной подложке `--illus-bg`, подпись под плиткой без номера, кнопка «+» — белый круг; кодовые рисунки перекрашены в светлые синие тона |
| Лайтбокс | графитовый фон, рамка с сеткой | светло-серый непрозрачный фон, картинка на градиентной панели с тенью, круглые кнопки, счётчик — «пилюля» |
| 03 Услуга | колонка с иконкой в рамке и «02.1 / Направление» | градиентная панель с иконкой в белом круге и кольцами, теги — «пилюли» |
| 04 Другие проекты | 3 равные карточки | одна крупная карточка слева + две строки с миниатюрой справа (от 1000 px; от 600 px — строки), как «Проекты» на главной B |
| CTA | тёмная полоса во всю ширину | тёмно-синяя скруглённая полоса по ширине контейнера с отступами сверху и снизу |

Номера в подписях секций B прячет без лишней разметки: у `.eyebrow` есть
атрибут `data-b-text` с подписью без номера, B показывает её псевдоэлементом
(для скринридера он «немой», читается сам текст элемента). Обёртка
`<span class="eyebrow__num">`, как на главной, сдвигала глифы A на субпиксель.

### Рисунки галереи

Пять иллюстраций — «схема», «спецификация», «перечень», «3D-сборка»,
«монтажная панель» — абстрактная геометрия без читаемых обозначений:
вместо текста полосы-заглушки, нижняя часть «спецификации» заштрихована и
размыта. Они вставлены в `project.html` inline, между маркерами
`<!-- gen:NAME -->` и `<!-- /gen:NAME -->`, и окрашены классами
`.art__*`/`.cover__*` через токены. После правки рисунков:

```sh
python3 tools/gen_gallery.py
```

Скрипт перезаписывает только содержимое между маркерами (повторный запуск
ничего не меняет).

## Шрифты

Self-hosted woff2 (только латиница и кириллица) в `assets/fonts/`,
подключаются в `assets/css/fonts.css`: IBM Plex Sans/Mono — концепция A,
Inter (300–600) — концепция B (браузер скачивает файлы шрифта, только когда
он действительно используется). Лицензии — в `CREDITS.md`.

## Доступность

Ссылка «Перейти к содержанию», видимый фокус (`:focus-visible`),
переключатель — настоящая `<button>` с `aria-label`, смена концепции
озвучивается через `role="status"`, мобильное меню с `aria-expanded` и
закрытием по Esc, `prefers-reduced-motion` отключает анимации. Контраст пар
«текст/фон» во всех токенах — не ниже WCAG AA.

## Проверка «нет внешних запросов»

```sh
python3 tools/check_external.py
```

Ищет абсолютные адреса (`http://`, `https://`, `//host`) во всех `.html`,
`.css`, `.js`, `.svg`, кроме комментариев и XML-пространств имён
(`xmlns="http://www.w3.org/..."` — это идентификатор, браузер его не
загружает). Код выхода 0 — внешних ссылок нет.
